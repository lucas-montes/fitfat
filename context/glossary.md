# FitFat — Glossary

| Term | Definition |
|------|------------|
| **Drift** | SQLite ORM for Dart/Flutter used as the persistence layer. |
| **@DataClass** | Drift annotation that generates a data class (row class) with `copyWith`, `toCompanion`, etc. |
| **Companion** | Drift-generated class for insert/update operations on a table row. |
| **StatefulShellRoute** | GoRouter route type that preserves child state when switching between branches (tabs). |
| **StatefulNavigationShell** | GoRouter widget that renders the current branch of a `StatefulShellRoute` and provides tab-switching methods. |
| **AppDatabase** | Central database class (`lib/src/database/app_database.dart`), annotated with `@DriftDatabase` listing all 16 tables. Migration `schemaVersion` is 19. |
| **PlannerItem** | Domain model for a daily planner task (`lib/src/models/planner_item.dart`); persisted in the `planner_items` table. |
| **planner_items** | Drift table storing per-day todo items: id, date (start-of-day epoch millis), title, done (0/1), sort_order, due_date (optional, v3), due_time_minutes (optional, v8 — minutes since midnight), notes (optional free-text, v6), created_at. |
| **BodyMetricsEntry** | Domain model for one day's weight/height entry (`lib/src/models/body_metrics_entry.dart`); persisted in the `body_metrics` table. |
| **body_metrics** | Drift table (v3) storing one row per day (keyed by start-of-day) with optional weight_kg and height_cm; no foreign keys. |
| **SettingsNotifier** | Riverpod `Notifier` (`lib/src/settings/providers/settings.dart`) holding app settings (themeMode, locale, age, bodyWeightGoal, gender, activityLevel, computeActivity, trackBodyFat, bodyFatPercent, plannerNotifications); persists via `settings_*` `shared_preferences` keys (see [settings/settings.md](settings/settings.md)). |
| **BodyWeightGoal** | Domain enum (`lib/src/models/body_weight_goal.dart`, app-polish-batch T02): `lose` / `maintain` / `gain`. Persisted under the `settings_body_weight_goal` prefs key via `SettingsNotifier.setBodyWeightGoal(...)` (null removes the key); `null` (unset) = no badge. Shown as a small "Goal: …" label on the dashboard weight-trend card header (see [settings/settings.md](settings/settings.md), [body-metrics.md](body/body-metrics.md)). |
| **sharedPreferencesProvider** | `Provider<SharedPreferences>` overridden in `main()` so settings load synchronously at startup. |
| **FlutterForegroundTask** | `flutter_foreground_task` package — ongoing Android foreground-service notification for active workouts. The task callback (`activeWorkoutTaskCallback`, top-level `@pragma('vm:entry-point')`) runs a `TaskHandler` in a background isolate where `shared_preferences` is available; notification text is rebuilt each 1 s tick from persisted keys (`active_workout_name`, `active_workout_started_at`, `rest_end_at`). See [notifications/notifications.md](notifications/notifications.md). |
| **FitFatTokens** | Design tokens in `lib/src/ui/tokens.dart` (spacing scale, radii, motion durations, `kContentMaxWidth` = 600) shared by the theme and `lib/src/ui/` widgets. |
| **FitFatColors** | `ThemeExtension<FitFatColors>` in `lib/src/ui/theme_extensions.dart` holding the only hand-picked colors: success / warning (+ `on*` variants), separate light and dark palettes meeting ≥ 4.5:1 contrast. Registered in both `FitFatTheme.light` and `FitFatTheme.dark`; read via `Theme.of(context).extension<FitFatColors>()`. |
| **StatusBadge** | Shared animated status pill widget (`lib/src/ui/widgets/status_badge.dart`): label text on a 15% alpha tint of a status color, `AnimatedContainer` color flip. Used for workout status pills (completed/active/pending). |
| **EmptyState** | Shared empty-state widget (`lib/src/ui/widgets/empty_state.dart`): tonal-circle icon + title + description + optional primary CTA (`ctaLabel`/`onCtaPressed`). Used as the empty state for every list screen (ingredients, meals, exercises, workouts, planner) and for the workout-detail no-exercises case (no CTA there). |
| **Welcome hub** | Dashboard first-run state (`_WelcomeHub` in `lib/src/dashboard/screens/dashboard.dart`): rocket icon + "Welcome to FitFat" + three action rows (add ingredient / log meal / add workout). Rendered when there are no meals AND no workouts; replaces the two data cards. |
| **Haptics** | Shared haptic-feedback helper (`lib/src/ui/haptics.dart`, T04): `Haptics.selection()` (planner checkbox toggles), `Haptics.mediumImpact()` (list deletes + ingredient swipe-to-archive), `Haptics.lightImpact()` (set-actuals save). Wraps `HapticFeedback.*`; no-op where unsupported. |
| **lib/src/ui/** | Design-system directory: tokens, `FitFatColors`, `DateFormats`, and shared widgets (StatusBadge, EmptyState, MetricCard). See [ui/design-system.md](ui/design-system.md). |
| **DateFormats** | Locale-aware date/time helper (`lib/src/ui/date_formats.dart`): `formatDate`/`formatShortDate`/`formatTime(TimeOfDay)` built on `MaterialLocalizations` (+ context-free `twoDigit`). Single formatting path for all calendar dates/clock times, rendering per active locale (en/fr/es). |
| **formatDecimal** | Shared number helper (`lib/src/ui/format.dart`, app-polish-batch T06): `String formatDecimal(double)` → whole when integral else one decimal ("12" / "12.5"). Single formatting path for set weights/distances and summary metrics (kg / m) in the workout detail, active-workout, and summary screens. |
| **completed_at** | `exercise_sets` column (schema v7, epoch millis) stamped by `updateSetActuals` (`completedAt: Value(DateTime.now().millisecondsSinceEpoch)`) whenever a set's actuals are saved (overwritten on re-edit); `null` for planned-only sets. `ExerciseSet.completedAt` domain field; snapshot restore round-trips it. Shown as a small HH:mm label (`DateFormats.formatTime`) on completed set rows in the active-workout screen only (app-polish-batch T08). Enables future rest-between-sets math (out of scope; `actualRestSeconds` remains today's rest source). |
| **is_archived** | `ingredients` column (schema v4, `NOT NULL DEFAULT 0`) implementing ingredient soft-archive. `getAll()` filters `is_archived == false`; `IngredientRepository.archive(id)`/`restore(id)` flip it; `Ingredient.isArchived` defaults false. No hard delete exists for ingredients. |
| **commonUndo** | Shared ARB string (en "Undo" / fr "Rétablir" / es "Deshacer") used as the Undo `SnackBarAction` label for ingredient archive (T05) and meal/workout/planner delete+undo (T07). |
| **WorkoutSnapshot** | Repo-local type (`lib/src/exercise/repositories/workout_repository.dart`, T06) returned by `WorkoutRepository.deleteWithSnapshot(id)`: raw Drift rows (`db.Workout`, `List<db.WorkoutExercise>`, `List<db.ExerciseSet>`) captured before deletion. `WorkoutRepository.restore(snapshot)` re-inserts all three levels with original ids and every column (incl. nullable actuals/notes) — the workout delete+undo path. |
| **usage-count block** | Exercise deletion guard (T07): `ExerciseRepository.usageCount(id)` counts `workout_exercises` rows referencing the exercise; the list screen checks it inside `Dismissible.confirmDismiss` and shows the blocking `exerciseUsedTitle`/`exerciseUsedBody` (plural) dialog when > 0, returning false so the tile snaps back and nothing is deleted. Unused exercises are hard-deleted with no Undo (user decision). |
| **Experiment** | Domain model for a self-tracking experiment (`lib/src/models/experiment.dart`); persisted in the `experiments` table (v18). Status enum `planned/active/done/aborted`; linked category enums `workout/diet/body/steps` (JSON `string[]` column). |
| **ExperimentCheckin** | Daily check-in (rating 1–5 + optional note) for an experiment (`lib/src/models/experiment.dart`); persisted in `experiment_checkins` (v18), one per experiment per day via the `(experiment_id, day)` unique key. `ExperimentRepository.upsertCheckin` replaces in place. |
| **experiment reminder** | Daily check-in notification (channel `experiment_reminders`, payload `experiment_reminder` → tap opens `/experiments`) scheduled by `ExperimentReminderScheduler` (`lib/src/experiments/notifications/experiment_reminder.dart`) at `reminderTimeMinutes` while an experiment is active, deterministically keyed by experiment id; cancelled on done/aborted/delete/disable. |
| **activeWorkoutProvider** | Riverpod `Provider<Workout?>` (`lib/src/exercise/providers/workouts.dart`, T08) deriving the currently active workout (`isActive` = started, not completed) from `workoutListProvider` (which every mutation site already invalidates). Consumed by the global floating bar (T08), the dashboard resume chip (T09), and `ActiveWorkoutScreen` (T04). |
| **Global active-workout bar** | Slim shell-level strip (T08; `_ActiveWorkoutBar` in `lib/src/app/router.dart`) shown above the `NavigationBar` on every tab while a workout is active: workout name + live elapsed `mm:ss` (1 s ticker, `formatRestDuration`) + play affordance (`activeWorkoutResume`). Tap or play → `GoRouter.of(context).go('/active-workout')` (T04). Rendered through an `AnimatedSwitcher` (slide + fade) in the shell's `bottomNavigationBar` column. |
| **ActiveWorkoutScreen** | The single dedicated view for a running workout (`lib/src/exercise/screens/active_workout_screen.dart`, active-workout-flow T04): watches `activeWorkoutProvider` + `workoutDetailProvider`; 1 s ticker live elapsed; per-exercise `ExpansionTile` set lists (planned column includes rest via `workoutDetailPlannedSetRest`), actuals dialog, rest-timer card, AppBar Complete action. |
| **/active-workout** | Top-level GoRouter route hosting `ActiveWorkoutScreen` — a **sibling** of `StatefulShellRoute.indexedStack`, outside every branch, so the floating bar + `NavigationBar` do not render on it. All active-workout entry points (floating bar, list active tap, dashboard chip/continue card, detail Start, and the notification tap since T06) reach it via `context.go(...)` / `appRouter.go(...)`. |
| **WorkoutSummaryScreen / /workout-summary/:id** | Read-only per-exercise summary of a completed workout (`lib/src/exercise/screens/workout_summary_screen.dart`, active-workout-flow T07) on a second top-level route outside the shell. Header: name, completed `StatusBadge`, total duration (`workout.duration`). Per exercise: **avg rest** = mean of `actualRestSeconds`, falling back to `restSeconds` for unrecorded sets (em-dash when none); **volume** = Σ `effectiveReps × effectiveWeightKg`; **max weight** = max `effectiveWeightKg`; **total reps** = Σ `effectiveReps`; cardio (any set with `durationMinutes`/`distanceMeters`) shows total duration Σ `durationMinutes ?? 0` + total distance Σ `distanceMeters ?? 0` instead. Reached from the completion flow and the completed-list tap via `context.go('/workout-summary/:id')`. |
| **todayCaloriesProvider** | Dashboard `FutureProvider<double>` (`lib/src/dashboard/providers/dashboard.dart`) summing `MealEntry.totalCalories` for meals whose `eatenAt` falls in today's start-of-day window. |
| **TodayMacros / todayMacrosProvider** | Dashboard `FutureProvider` of `({double protein, double carbs, double fat})` (typedef `TodayMacros`) summing per-item `MealIngredient.protein/carbs/fat` grams in today's window — the read-only P/C/F composition data for the hero card (T09). |
| **MetricCard** | Shared stat-card shell (`lib/src/ui/widgets/metric_card.dart`): icon + title + value (+ `trailing`, `subtitle`, optional `child` slot). The value renders inside an `AnimatedSwitcher` keyed by the string (hero-number animation). Consumed by the dashboard hero calories card (T09). |
| **dueTimeMinutes** | `planner_items.due_time_minutes` column (schema v8): optional due time-of-day as minutes since midnight. `PlannerItem.dueTimeMinutes`; drives the planner due-time tile subtitle and the task-reminder notifications. |
| **TaskReminderScheduler** | `lib/src/notifications/task_reminders.dart` (T11): schedules the 30-min pre-reminder + due-time `flutter_local_notifications` reminders for timed planner tasks, cancels on done/delete/edit, and provides `cancelAll()` / `reschedulePending(repository)` for the app-wide `plannerNotifications` toggle. Deterministic per-task ids (FNV-1a) + a prefs registry of scheduled task ids. |
| **plannerNotifications** | `SettingsState` bool (default **true**, key `settings_planner_notifications`): the single app-wide task-reminder toggle. Off cancels all scheduled planner reminders; on restores pending future timed tasks. |
| **plannerReminderTimes** | Pure helper in `task_reminders.dart` returning the local wall-clock instants for a task's reminders (`[pre, due]`, `[due]`, or `[]`); past-due/done/untimed tasks return empty (they never schedule). |
| **splitTags** | Pure helper in `exercise_filter.dart` (exercise filters/metadata): splits a comma-separated catalog value ("Quadriceps, Thighs") into distinct, trimmed tags — the basis for filter options and fact chips. |
| **canonicalEquipmentTag** | Pure helper in `exercise_filter.dart` mapping equipment synonyms to canonical labels (`Band`→`Resistance Band`, `Olympic barbell`→`Barbell`), mirroring `tool/build_catalog.dart`, so combined values filter/display consistently. |
| **exerciseFilterOptions / filterExercises** | Pure filter helpers in `exercise_filter.dart`: `exerciseFilterOptions(List<Exercise>)` derives distinct sorted Type/Body-part/Equipment/Muscle options; `filterExercises(exercises, {query, types, bodyParts, equipments, muscles})` ANDs tag filters and matches the query against name / keywords (hidden from display) / muscles, case-insensitive. |
| **updateCatalog** | `ExerciseRepository.updateCatalog(Exercise)` — writes all metadata columns for a locked row; the importer refresh path (flag `catalog_imported_v9`) that refreshes previously-imported catalog rows in place without touching user rows. |
| **video_allowlist.txt** | `tool/video_allowlist.txt` — the 16 curated video slugs bundled with the app; only these get a `videoPath` in the catalog, are copied by `tool/prepare_media.sh`, and are registered as explicit `pubspec.yaml` asset entries. |
| **Structured FAQs** | The `exercises.faqs` column stores JSON `[{"q","a"},…]` (parsed by `tool/build_catalog.dart` from the scraped FAQ blob); `_FaqSection` in the detail screen decodes it into Q/A blocks, falling back to raw text when unparseable. |
| **Fact chips** | Pinned header chips on the exercise detail screen (type / body-part / equipment via `splitTags` + `canonicalEquipmentTag`); muscles live in the Details tab. |
| **ApiClient** | Abstract HTTP interface (`lib/src/network/api_client.dart`, Phase E): `getJson`/`postJson`/`putJson`/`deleteJson` returning decoded JSON; `HttpApiClient` (production `package:http`, timeout + User-Agent + base URL) and `MockApiClient` (scripted responses) implement it; exposed via the overridable `apiClientProvider`. |
| **HttpApiClient** | Production `ApiClient` (`lib/src/network/api_client.dart`): `package:http.Client` with a 15 s timeout, JSON headers + `User-Agent: FitFat/1.0`, UTF-8 decode, throws `ApiException` on non-2xx. |
| **MockApiClient** | Scripted `ApiClient` for tests: an `onRequest(method, path, body)` callback returns canned decoded JSON (or throws); no handler → `null`. |
| **apiClientProvider** | `Provider<ApiClient>` defaulting to `HttpApiClient` at the compile-time `API_BASE_URL`; overridable in `ProviderScope` (tests inject `MockApiClient`). |
| **FxRateRemoteService** | Real FX backend (`lib/src/budget/services/remote_fx.dart`, Phase E): `implements RemoteFxService` over an `ApiClient` + `fxRatesApiBaseUrl` (`FX_API_BASE_URL`, empty until a provider is chosen). Serves `remoteFxProvider`; fetch throws a clear error while unconfigured. |
| **Routine / replay lineage** | `workouts.routine_id` (schema v21): all occurrences created by **Replay** share one UUID so a routine is countable (`getRoutineCompletionCount` = completed occurrences). `replayWorkout` prefills the new pending occurrence from the previous completion's actuals (or planned, per `settings_replay_prefill`), strips trailing " #N"/" (Copy)" from the name, and stamps today's date. Contrast **Duplicate** (`copyWorkout`): an identity-fresh independent copy with no lineage. |
