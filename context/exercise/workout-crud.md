# Workout CRUD — Exercise Domain

Feature: create, read, update, and delete workouts. Supports a pending→active→completed workflow and logging actual set data.

## Files

| File | Purpose |
|------|---------|
| `lib/src/exercise/repositories/workout_repository.dart` | Drift DAO for `workouts` + `workout_exercises` + `exercise_sets` tables |
| `lib/src/exercise/providers/workouts.dart` | Riverpod providers (`workoutRepositoryProvider`, `workoutListProvider`, `workoutDetailProvider`) |
| `lib/src/exercise/screens/workout_list.dart` | ListView with status badges (Pending/Active/Completed), swipe-to-delete |
| `lib/src/exercise/screens/workout_form.dart` | Name, date picker, exercise multi-select with editable planned sets (reps/weight or duration) |
| `lib/src/exercise/screens/workout_detail.dart` | Pending (planning) screen: exercises with sets, log actual values per set via dialog, Start button |
| `lib/src/exercise/screens/active_workout_screen.dart` | Single dedicated view for a running workout (top-level route `/active-workout`, outside the shell) |
| `lib/src/exercise/screens/workout_summary_screen.dart` | Read-only per-exercise summary of a completed workout (top-level route `/workout-summary/:id`, outside the shell) |

## Key behavior

- **Repository**: Transactional insert/delete across 3 tables. Loads full workout tree via batched queries. Supports `start()` (sets `startedAt`) and `complete()` (sets `completedAt`). Set rest is persisted since schema v5: `insert`/`restore`/detail-loading round-trip `rest_seconds` (planned) and `actual_rest_seconds` (recorded), and `recordSetRest({setId, actualRestSeconds})` writes the actual rest taken. `newPlannedSet()` takes a `restSeconds` param (active-workflow T01); the form requires rest for every added set (T03). `updateSetActuals` stamps `exercise_sets.completed_at` (`DateTime.now()`, epoch millis) whenever any actual value is saved — overwritten on re-edit, null for planned-only sets (app-polish-batch T08); snapshot restore round-trips it.
- **Rich result types**: `WorkoutWithDetails` (workout + `List<ExerciseBlock>`), `ExerciseBlock` (workout_exercise + `List<ExerciseSet>`).
- **Delete + restore (T06)**: `deleteWithSnapshot(String id)` deletes the workout, its `workout_exercises`, and all their `exercise_sets` inside one transaction and returns a `WorkoutSnapshot` of every row removed (raw Drift rows, so nothing is lost). `restore(WorkoutSnapshot)` re-inserts all three levels with original ids and every column — including nullable `started_at`/`completed_at`/`notes` and set actuals/notes (exact round-trip). Throws `StateError` if the workout row is missing before deleting anything. `WorkoutSnapshot` is defined locally in the repository file.
- **Form**: Search-first exercise picker — nothing is listed until the user types; the search field (`workoutFormSearchHint`) filters case-insensitively and tapping a result adds the exercise (multi-select; an already-added row shows a check; each selected exercise card has a remove action with `workoutFormRemoveExercise` tooltip). Result rows show a 48×48 thumbnail (catalog image, type-icon fallback — quick-wins T02). Selecting an exercise creates **no sets** — each set is added explicitly via "Add set" (empty entry, no pre-filled values). Per-set editors: reps/weight + **rest** for weightlifting, duration + **rest** for cardio; rest is entered in **minutes** (decimal allowed) and stored as `rest_seconds` (×60) on the plan (T03). Every added set must be complete — reps/weight (or duration) AND rest > 0 — or save is blocked with a `workoutFormSetIncomplete` top banner; exercises with zero added sets stay allowed. Uses `newWorkout()`, `newWorkoutExercise()`, `newPlannedSet(restSeconds:)` factory helpers.
- **List screen**: Shows date + status badge. Exercise definitions accessible via AppBar action. Swipe-to-delete → `deleteWithSnapshot` + `workoutDeleted(name)` top banner with Undo (`commonUndo`) → `restore(snapshot)` + invalidate; no confirm dialog (T07); `Haptics.mediumImpact` on delete (T04). Empty state = `EmptyState` (`fitness_center`, `emptyWorkouts*` ARB keys) with a CTA that opens the workout form (T03).
- **Form screen**: on successful save pops `true` (the list refreshes via provider invalidation); failures surface through the error top banner.
- **Detail screen (pending-only since T04)**: Header card with status/date/duration. Exercise `ExpansionTile` showing set rows. Planned values shown strikethrough when actuals logged. Tappable rows open dialog to log actuals; saving actuals fires `Haptics.lightImpact` (T04). Set rows use flex columns (`Expanded(flex: 2)` set-number / `flex: 5` planned / `flex: 5` actual) so they wrap instead of clipping at large text scales; the edit affordance carries a `commonEdit` tooltip (T10). In the planning view's `_ExerciseBlockCard` the **planned sets render as a vertical `Column` of full-width set rows** (one per line; quick-wins T01). Set weight/distance values render via the shared `formatDecimal` helper — whole when integral, one decimal only when fractional ("12 kg" / "12.5 kg") (app-polish-batch T06). The AppBar Start button (pending only) starts the workout notification then redirects to the active view: `Navigator.pop()` (the imperatively-pushed planning detail) + `router.go('/active-workout')` — go_router 15 can't remove imperative routes, so pop-then-go replaces it with no back to planning. The Complete action and active header branches moved to `ActiveWorkoutScreen` (T04). A workout with no exercises shows `EmptyState` (`fitness_center`, `emptyWorkoutDetailTitle/Body` — **no CTA**, no edit-workout flow exists; T03). Saving actuals invalidates `workoutDetailProvider(workout.id)` so the view refreshes immediately (app-improvements T09 — the provider is keyed by workout id, not workout_exercise id).
- **ActiveWorkoutScreen (active-workout-flow T04, auto-rest T05)**: the one view for a running workout, on the top-level `/active-workout` route (outside the shell → no floating bar / `NavigationBar`). Watches `activeWorkoutProvider` (identity) + `workoutDetailProvider` (sets); 1 s ticker renders live elapsed time (header Active `StatusBadge` + started-at). Every `AppBar` variant (not-found ×2, loading, error, data) carries a leading back button (`_activeWorkoutBackButton`) that pops when `canPop()` else `context.go('/exercise')` (app-polish-batch T07). Per-exercise `ExpansionTile` set lists — the planned column appends rest via `workoutDetailPlannedSetRest` (`· rest mm:ss`); set rows are tappable (actuals dialog, same as detail); set weight/distance values use the shared `formatDecimal` helper (one decimal only when fractional, app-polish-batch T06). Completed set rows (actuals recorded) additionally show the set's completion time as a small HH:mm label under the actual value via `DateFormats.formatTime` from `set.completedAt` (app-polish-batch T08; pending detail and summary never show it). **Completing a set auto-starts the rest timer with that set's planned rest** (`set.restSeconds`), skipped when no other incomplete set remains (checked against the cached detail) or the set has no planned rest (T05); the actual rest is recorded on the set when the rest ends, is cancelled early, or the workout completes (`recordSetRest` inside `cancelRest()` — see [notifications.md](../notifications/notifications.md)). Manual preset chips still start a rest without a set target (not recorded). Rest-timer card (preset chips + cancel) and the AppBar Complete action (cancel rest → stop notification → `complete()` → invalidate detail+list → `context.go('/workout-summary/$id')`) live here. Entry points — all via `context.go('/active-workout')`: floating bar tap/play, workout-list active tap, dashboard resume chip + continue card, and the detail Start flow (pop-then-go).
- **Active workout redo (2026-08-17 review)**: the per-exercise card in `ActiveWorkoutScreen` (`_ExercisePage`) now shows, top to bottom: a **compact media strip** (`_CompactMedia`, 110 pt — bundled thumbnail, tap → full-screen zoomable `_CardImageViewer`; inline `video_player` play/pause when a bundled video asset initializes, with graceful image fallback), a header row (name + set count + **note affordance**), optional **fact chips** (`_CardFactChips`, type/body-part/equipment pills), then the scroll list: a **per-exercise progress bar** (`_SetsProgressBar`, `completed/total` sets), a **collapsible history** (`_ExerciseHistorySection` + `_ExerciseHistoryRow` — past sessions via `exerciseHistoryProvider(exerciseId)`: workout name/date + volume-or-duration + completed/total sets; hidden while loading, error, or empty), then the set rows. **Notes** (exercise-level) are stored in `workout_exercises.notes` (schema v17; threaded through insert/replace/restore/copy + `_getExerciseBlocks`); the card's `add_comment`/`comment` `IconButton` (or the rendered note, which is tappable) opens `_NoteDialog` (multiline, `activeWorkoutExerciseNotes*` keys) and saves via `updateExerciseNotes({workoutExerciseId, notes})` then invalidates `workoutDetailProvider(workout.id)`. **Set rows** (`_SetRow`) were redesigned: no left set number and no `lineThrough` on planned; planned renders as a small muted subtext above a prominent actual headline; a leading status icon plus row tint and actual-line color encode `_SetProgress` — `pending` (unlogged, outline) / `partial` (0 < logged < planned, `FitFatColors.warning`) / `done` (logged ≥ planned, `FitFatColors.success`) / `failed` (logged at zero, `colorScheme.error`) via `_setProgress`/`_statusVisuals` (weightlifting compares reps; cardio compares duration/distance). Tap-to-edit the actuals dialog, the reversed HH:mm completion stamp, and rest auto-start are unchanged.
- **Active workout performance (perf 2026-08-17)**: the whole-screen 1 s ticker was removed — `_ElapsedText` (a leaf `StatefulWidget`) owns its own `Timer.periodic` so the per-second `setState` rebuilds only the elapsed text (the rest line `_RestLine` has its own scoped ticker). The search sheet debounces `_searchCtrl` input (250 ms `Timer`, mirroring `exercise_picker_sheet.dart`) and memoizes `exerciseFilterOptions` in state keyed on the exercise list instance (no full-catalog recompute per keystroke). `_getExerciseBlocks` and `getExerciseHistory` each issue one `workoutExerciseId.isIn(...)` sets query and group in memory; the dashboard weekly stats use the new `getVolumeAndMinutesSince(weekStart)` bulk method (a join for volume + a workouts scan for duration) instead of per-workout `workoutDetailProvider` resolution.
- **Active workout declutter (2026-08-19 review)**: the two top cards merged into **one info strip** — row 1 = Active `StatusBadge` + the `N / M` page indicator (moved up from the pager bar, which is prev/next buttons only now); row 2 = live elapsed (`_ElapsedText`) + started-at; row 3 = the rest line (`_RestLine`, replaces `_RestStrip`: count-up with overdue highlight, own scoped 1 s ticker, shows `· <exercise name>` when the user swiped away from the resting set's exercise). Per-exercise card decluttering: **fact chips moved behind an info icon** (`Icons.info_outline` → bottom sheet with the name + `_CardFactChips`) and the **history ExpansionTile moved behind a history icon** (`Icons.history` → draggable bottom sheet, `_HistorySheet`, reusing `_ExerciseHistoryRow`; short empty-state text when nothing completed) — the note affordance/rendered note stay inline. **Set markings now compare weight**: `_setProgress` marks `partial` when reps *or* `actualWeightKg` is below planned (weight was informational before); done/failed/pending unchanged. **History counts only completed work**: `getExerciseHistory` filters workouts to `completed_at IS NOT NULL`, keeps only `set.isCompleted` rows, and drops entries with zero completed sets — consumers aggregate from returned sets, so the active screen history sheet and the exercise-detail History tab both exclude pending workouts/planned sets automatically. **Rest-complete jump (one-shot)**: the content watches `restTimerProvider`; on the transition to overdue it maps `rest.setId` → exercise page index and `jumpToPage`s back once per rest session (keyed on `rest.startedAt`, `_lastJumpedRestStart`); the manual pager is otherwise untouched.
- **WorkoutSummaryScreen (active-workout-flow T07)**: read-only summary of a completed workout on the top-level `/workout-summary/:id` route (outside the shell → no floating bar / `NavigationBar`). Watches `workoutDetailProvider(workoutId)`; loading/error/not-found states carry a back affordance that pops when possible else `go('/exercise')`. Header card: name, completed `StatusBadge`, total duration (`workout.duration` via `formatRestDuration`). Per-exercise card (`_ExerciseMetrics.fromBlock`): **avg rest** = mean of `actualRestSeconds`, falling back to `restSeconds` for sets with no recorded actual rest (em-dash when the exercise has no rest info); **volume** = Σ `set.totalVolume` (effective reps × effective weight); **max weight** = max `effectiveWeightKg`; **total reps** = Σ `effectiveReps`. An exercise is **cardio when any of its sets** logged `durationMinutes`/`distanceMeters` (per-set classification elsewhere in the app; the summary's unit is the exercise — documented in code); cardio shows total duration Σ `durationMinutes ?? 0` + total distance Σ `distanceMeters ?? 0` instead of volume/max-weight/reps. Values: whole-or-one-decimal via the shared `formatDecimal` helper (kg / m), rest/duration via `formatRestDuration`. Entry points via `context.go('/workout-summary/:id')`: the ActiveWorkoutScreen Complete flow, the workout-list completed tap, and the dashboard latest-workout card completed tap (T08). `WorkoutDetailScreen` is now exclusively the pending (planning) screen — its only remaining entry point is the workout-list pending tap; the workout-level completed/active branches were removed from it in T08 (set-level `set.isCompleted` strikethrough styling remains).
- **Active workout notifications (app-improvements T10, moved T04)**: Start persists the session and starts the ongoing Android foreground notification (duration + remaining rest) via `flutter_foreground_task` — still wired to the detail Start button; Complete (now on `ActiveWorkoutScreen`) cancels the rest and stops the notification. See [notifications.md](../notifications/notifications.md).
- **Global active-workout bar (ui-ux-improvements T08)**: `activeWorkoutProvider` (in `workouts.dart`) derives the active workout (`isActive` = started, not completed) from `workoutListProvider` — no dedicated query, all mutation sites already invalidate the list. The shell (`_ShellWithNavBar` in `router.dart`, a `ConsumerWidget`) shows the bar above the `NavigationBar` on every tab while one is active: name, live elapsed `mm:ss` (`formatRestDuration` + 1 s ticker), `StatusBadge` "Active", play affordance (`activeWorkoutResume`). Tap or play → `GoRouter.of(context).go('/active-workout')` (T04) — the active screen replaces the detail, never stacks another copy. The bar sits in the `bottomNavigationBar` column so FABs float clear; it animates in/out via `AnimatedSwitcher`. The dashboard resume chip (T09) consumes the same provider and also routes to `/active-workout`.
- **Workout replay + lineage (workout-replay, 2026-08-22)**: `workouts.routine_id` (schema v21, indexed) links every occurrence of the same routine. `WorkoutRepository.replayWorkout({sourceWorkoutId, prefill, date})` builds the next pending occurrence: same exercises (notes kept), planned sets prefilled from the source's **actuals** (`reps`←`actualReps`, `weightKg`←`actualWeightKg`, duration/distance likewise; unlogged sets fall back to their planned values) or from the planned values per `prefill` ('actuals' default | 'planned' — the `settings_replay_prefill` setting), trailing " #N"/" (Copy)" stripped from the name, date = today, and `routineId` = the source's or a fresh UUID. `getRoutineCompletionCount(routineId)` counts completed occurrences in one grouped query ("times done"). Surfaces: **summary AppBar "Do again"** (`Icons.replay`) and the **list tile long-press sheet** (Replay / Duplicate); both run replay then push the editable `WorkoutFormScreen(initial: newDetail)` and invalidate list + dashboard. **Duplicate** (`copyWorkout`) stays as the independent, identity-fresh copy with no lineage.

## Workflow

```
Pending (startedAt=null) → Start → Active (startedAt=set) → Complete → Completed (completedAt=set)
```

## Wiring

The Exercise tab (`lib/src/app/tabs/exercise_tab.dart`) renders `WorkoutListScreen`. Exercise definitions are accessible via the AppBar action (`fitness_center` icon) which pushes `ExerciseListScreen`.
