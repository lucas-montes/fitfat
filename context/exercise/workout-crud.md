# Workout CRUD — Exercise Domain

Feature: create, read, update, and delete workouts. Supports a pending→active→completed workflow and logging actual set data.

## Files

| File | Purpose |
|------|---------|
| `lib/src/exercise/repositories/workout_repository.dart` | Drift DAO for `workouts` + `workout_exercises` + `exercise_sets` tables |
| `lib/src/exercise/providers/workouts.dart` | Riverpod providers (`workoutRepositoryProvider`, `workoutListProvider`, `workoutDetailProvider`) |
| `lib/src/exercise/screens/workout_list.dart` | ListView with status badges (Pending/Active/Completed), swipe-to-delete |
| `lib/src/exercise/screens/workout_form.dart` | Name, date picker, exercise multi-select with editable planned sets (reps/weight or duration) |
| `lib/src/exercise/screens/workout_detail.dart` | Pending (planning) screen: exercises with sets, log actual values per set via dialog, Start button |
| `lib/src/exercise/screens/active_workout_screen.dart` | Single dedicated view for a running workout (top-level route `/active-workout`, outside the shell) |
| `lib/src/exercise/screens/workout_summary_screen.dart` | Read-only per-exercise summary of a completed workout (top-level route `/workout-summary/:id`, outside the shell) |

## Key behavior

- **Repository**: Transactional insert/delete across 3 tables. Loads full workout tree via batched queries. Supports `start()` (sets `startedAt`) and `complete()` (sets `completedAt`). Set rest is persisted since schema v5: `insert`/`restore`/detail-loading round-trip `rest_seconds` (planned) and `actual_rest_seconds` (recorded), and `recordSetRest({setId, actualRestSeconds})` writes the actual rest taken. `newPlannedSet()` takes a `restSeconds` param (active-workflow T01); the form requires rest for every added set (T03). `updateSetActuals` stamps `exercise_sets.completed_at` (`DateTime.now()`, epoch millis) whenever any actual value is saved — overwritten on re-edit, null for planned-only sets (app-polish-batch T08); snapshot restore round-trips it.
- **Rich result types**: `WorkoutWithDetails` (workout + `List<ExerciseBlock>`), `ExerciseBlock` (workout_exercise + `List<ExerciseSet>`).
- **Delete + restore (T06)**: `deleteWithSnapshot(String id)` deletes the workout, its `workout_exercises`, and all their `exercise_sets` inside one transaction and returns a `WorkoutSnapshot` of every row removed (raw Drift rows, so nothing is lost). `restore(WorkoutSnapshot)` re-inserts all three levels with original ids and every column — including nullable `started_at`/`completed_at`/`notes` and set actuals/notes (exact round-trip). Throws `StateError` if the workout row is missing before deleting anything. `WorkoutSnapshot` is defined locally in the repository file.
- **Form**: Search-first exercise picker — nothing is listed until the user types; the search field (`workoutFormSearchHint`) filters case-insensitively and tapping a result adds the exercise (multi-select; an already-added row shows a check; each selected exercise card has a remove action with `workoutFormRemoveExercise` tooltip). Selecting an exercise creates **no sets** — each set is added explicitly via "Add set" (empty entry, no pre-filled values). Per-set editors: reps/weight + **rest** for weightlifting, duration + **rest** for cardio; rest is entered in **minutes** (decimal allowed) and stored as `rest_seconds` (×60) on the plan (T03). Every added set must be complete — reps/weight (or duration) AND rest > 0 — or save is blocked with a `workoutFormSetIncomplete` SnackBar; exercises with zero added sets stay allowed. Uses `newWorkout()`, `newWorkoutExercise()`, `newPlannedSet(restSeconds:)` factory helpers.
- **List screen**: Shows date + status badge. Exercise definitions accessible via AppBar action. Swipe-to-delete → `deleteWithSnapshot` + `workoutDeleted(name)` SnackBar with Undo (`commonUndo`) → `restore(snapshot)` + invalidate; no confirm dialog (T07); `Haptics.mediumImpact` on delete (T04). Empty state = `EmptyState` (`fitness_center`, `emptyWorkouts*` ARB keys) with a CTA that opens the workout form (T03).
- **Form screen**: on successful save shows a `commonSaved` SnackBar (root `ScaffoldMessenger`, persists across the pop) then pops `true` (T04).
- **Detail screen (pending-only since T04)**: Header card with status/date/duration. Exercise `ExpansionTile` showing set rows. Planned values shown strikethrough when actuals logged. Tappable rows open dialog to log actuals; saving actuals fires `Haptics.lightImpact` (T04). Set rows use flex columns (`Expanded(flex: 2)` set-number / `flex: 5` planned / `flex: 5` actual) so they wrap instead of clipping at large text scales; the edit affordance carries a `commonEdit` tooltip (T10). Set weight/distance values render via the shared `formatDecimal` helper — whole when integral, one decimal only when fractional ("12 kg" / "12.5 kg") (app-polish-batch T06). The AppBar Start button (pending only) shows a `workoutStarted` SnackBar then redirects to the active view: `Navigator.pop()` (the imperatively-pushed planning detail) + `router.go('/active-workout')` — go_router 15 can't remove imperative routes, so pop-then-go replaces it with no back to planning. The Complete action, rest card, and active header branches moved to `ActiveWorkoutScreen` (T04). A workout with no exercises shows `EmptyState` (`fitness_center`, `emptyWorkoutDetailTitle/Body` — **no CTA**, no edit-workout flow exists; T03). Saving actuals invalidates `workoutDetailProvider(workout.id)` so the view refreshes immediately (app-improvements T09 — the provider is keyed by workout id, not workout_exercise id).
- **ActiveWorkoutScreen (active-workout-flow T04, auto-rest T05)**: the one view for a running workout, on the top-level `/active-workout` route (outside the shell → no floating bar / `NavigationBar`). Watches `activeWorkoutProvider` (identity) + `workoutDetailProvider` (sets); 1 s ticker renders live elapsed time (header Active `StatusBadge` + started-at). Every `AppBar` variant (not-found ×2, loading, error, data) carries a leading back button (`_activeWorkoutBackButton`) that pops when `canPop()` else `context.go('/exercise')` (app-polish-batch T07). Per-exercise `ExpansionTile` set lists — the planned column appends rest via `workoutDetailPlannedSetRest` (`· rest mm:ss`); set rows are tappable (actuals dialog, same as detail); set weight/distance values use the shared `formatDecimal` helper (one decimal only when fractional, app-polish-batch T06). Completed set rows (actuals recorded) additionally show the set's completion time as a small HH:mm label under the actual value via `DateFormats.formatTime` from `set.completedAt` (app-polish-batch T08; pending detail and summary never show it). **Completing a set auto-starts the rest timer with that set's planned rest** (`set.restSeconds`), skipped when no other incomplete set remains (checked against the cached detail) or the set has no planned rest (T05); the actual rest is recorded on the set when the rest ends, is cancelled early, or the workout completes (`recordSetRest` inside `cancelRest()` — see [notifications.md](../notifications/notifications.md)). Manual preset chips still start a rest without a set target (not recorded). Rest-timer card (preset chips + cancel) and the AppBar Complete action (cancel rest → stop notification → `complete()` → invalidate detail+list → `context.go('/workout-summary/$id')`) live here. Entry points — all via `context.go('/active-workout')`: floating bar tap/play, workout-list active tap, dashboard resume chip + continue card, and the detail Start flow (pop-then-go).
- **WorkoutSummaryScreen (active-workout-flow T07)**: read-only summary of a completed workout on the top-level `/workout-summary/:id` route (outside the shell → no floating bar / `NavigationBar`). Watches `workoutDetailProvider(workoutId)`; loading/error/not-found states carry a back affordance that pops when possible else `go('/exercise')`. Header card: name, completed `StatusBadge`, total duration (`workout.duration` via `formatRestDuration`). Per-exercise card (`_ExerciseMetrics.fromBlock`): **avg rest** = mean of `actualRestSeconds`, falling back to `restSeconds` for sets with no recorded actual rest (em-dash when the exercise has no rest info); **volume** = Σ `set.totalVolume` (effective reps × effective weight); **max weight** = max `effectiveWeightKg`; **total reps** = Σ `effectiveReps`. An exercise is **cardio when any of its sets** logged `durationMinutes`/`distanceMeters` (per-set classification elsewhere in the app; the summary's unit is the exercise — documented in code); cardio shows total duration Σ `durationMinutes ?? 0` + total distance Σ `distanceMeters ?? 0` instead of volume/max-weight/reps. Values: whole-or-one-decimal via the shared `formatDecimal` helper (kg / m), rest/duration via `formatRestDuration`. Entry points via `context.go('/workout-summary/:id')`: the ActiveWorkoutScreen Complete flow, the workout-list completed tap, and the dashboard latest-workout card completed tap (T08). `WorkoutDetailScreen` is now exclusively the pending (planning) screen — its only remaining entry point is the workout-list pending tap; the workout-level completed/active branches were removed from it in T08 (set-level `set.isCompleted` strikethrough styling remains).
- **Active workout notifications (app-improvements T10, moved T04)**: Start persists the session and starts the ongoing Android foreground notification (duration + remaining rest) via `flutter_foreground_task` — still wired to the detail Start button; Complete (now on `ActiveWorkoutScreen`) cancels the rest and stops the notification. See [notifications.md](../notifications/notifications.md).
- **Global active-workout bar (ui-ux-improvements T08)**: `activeWorkoutProvider` (in `workouts.dart`) derives the active workout (`isActive` = started, not completed) from `workoutListProvider` — no dedicated query, all mutation sites already invalidate the list. The shell (`_ShellWithNavBar` in `router.dart`, a `ConsumerWidget`) shows the bar above the `NavigationBar` on every tab while one is active: name, live elapsed `mm:ss` (`formatRestDuration` + 1 s ticker), `StatusBadge` "Active", play affordance (`activeWorkoutResume`). Tap or play → `GoRouter.of(context).go('/active-workout')` (T04) — the active screen replaces the detail, never stacks another copy. The bar sits in the `bottomNavigationBar` column so FABs float clear; it animates in/out via `AnimatedSwitcher`. The dashboard resume chip (T09) consumes the same provider and also routes to `/active-workout`.

## Workflow

```
Pending (startedAt=null) → Start → Active (startedAt=set) → Complete → Completed (completedAt=set)
```

## Wiring

The Exercise tab (`lib/src/app/tabs/exercise_tab.dart`) renders `WorkoutListScreen`. Exercise definitions are accessible via the AppBar action (`fitness_center` icon) which pushes `ExerciseListScreen`.
