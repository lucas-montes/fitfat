# Exercise Definition CRUD + Catalog — Exercise Domain

Feature: create, read, update, and delete exercise definitions (name + type: weightlifting/cardio), plus the server-synced exercise catalog (schema v8 metadata + locked rows), its background refresh and selective import, search + tag filters, and the tabbed detail/history screen.

## Files

| File | Purpose |
|------|---------|
| `lib/src/exercise/repositories/exercise_repository.dart` | Drift DAO wrapping the `exercises` table (incl. v8 metadata columns) |
| `lib/src/exercise/providers/exercises.dart` | Riverpod providers (`exerciseRepositoryProvider`, `exerciseListProvider`, `exerciseByIdProvider`) |
| `lib/src/exercise/exercise_filter.dart` | Pure helpers: `splitTags`, `canonicalEquipmentTag`, `exerciseFilterOptions`, `filterExercises` |
| `lib/src/exercise/screens/exercise_list.dart` | Search + Type/Body part/Equipment/Muscle filter chips, tap → detail, long-press → edit, swipe-to-delete |
| `lib/src/exercise/screens/exercise_form.dart` | Form with name + type dropdown |
| `lib/src/exercise/screens/exercise_detail_screen.dart` | Pinned header (media + name + fact chips) + History/Details tabs |
| `lib/src/exercise/services/catalog_importer.dart` | **Gone.** The bundled catalog importer was removed with the bundled assets; the catalog now arrives from the server |
| `lib/src/sync/catalog_sync_client.dart` | The catalogue client: `refreshExercises` / `refreshIngredients` against the server's `/exercises/catalog` and `/ingredients/catalog` endpoints, and `importExercises` / `importIngredients` for a selective import |
| `lib/src/sync/exercise_media_sync.dart` | Downloads an exercise's image and video from the server (`<baseUrl>/exercises/<id>.jpg` / `.mp4`) into `<application documents>/exercise_media/`, keyed by exercise id. No URL is ever stored — `imagePath` / `videoPath` hold local file paths |

## Key behavior

- **Repository** (`exercise_repository.dart`): Uses `ExercisesCompanion.insert()` for inserts and `ExercisesCompanion()` for updates. `updateCatalog(Exercise)` (filters/metadata cleanup) writes all metadata columns for a locked row (used by the importer refresh). Orders results alphabetically by name. `usageCount(String id)` (T06) returns how many `workout_exercises` rows reference the exercise (single `SELECT COUNT(*)` via `selectOnly`) — used to block deletion of exercises still used in workouts. The v8 metadata columns round-trip through `insert`/`_toDomain` (`isLocked`, `bodyPart`, `equipment`, `primaryMuscle`, `secondaryMuscle`, `instructions`/`tips`/`keywords` as JSON-encoded `List<String>`, `faqs` (structured JSON `[{"q","a"},…]`), `imagePath`, `videoPath`).
- **Helper** `newExercise()`: Creates a domain `Exercise` with a fresh UUID v7 and `DateTime.now()`; user-created exercises are not locked.
- **Providers** (`exercises.dart`): `exerciseRepositoryProvider`, `exerciseListProvider` (FutureProvider), `exerciseByIdProvider` (FutureProvider.family, resolves to `null` when the id doesn't exist — the detail screen's not-found state). `exerciseHistoryProvider` lives in `lib/src/exercise/providers/workouts.dart` (family by exercise id → `WorkoutRepository.getExerciseHistory`). All use shared `databaseProvider` from `lib/src/database/database_provider.dart`.
- **List screen**: `ConsumerStatefulWidget` with a **search field** + **filter chips** (Type / Body part / Equipment / Muscle) that open a searchable multi-select bottom sheet (`_FilterOptionsSheet`, checkboxes + Clear/Apply). Query matches name **or keywords** (hidden from display) **or muscles**; filters are AND-ed. A results-count row + "Clear all" appears when filters are active; `_FilteredEmptyState` when nothing matches. Filtering is backed by pure helpers in `exercise_filter.dart` (`exerciseFilterOptions` derives distinct sorted options from the loaded list; `filterExercises` applies query + tag filters; `canonicalEquipmentTag` maps `Band`→`Resistance Band` / `Olympic barbell`→`Barbell` so combined values filter consistently). Tile interactions unchanged: **tap → `ExerciseDetailScreen(exerciseId:)`** (T06); **long-press → edit form** — blocked for locked exercises with the `exerciseLockedEdit` top banner (T06). `Dismissible.confirmDismiss` first blocks locked exercises with the `exerciseLockedDelete` top banner, then checks `usageCount(id)` (T06): if > 0 it shows the blocking `exerciseUsedTitle` + `exerciseUsedBody(count)` (plural) dialog with `commonOk` and returns false — the tile snaps back, nothing is deleted/throws; unused exercises pass through to a plain hard delete with **no Undo** (user decision, T07). `Haptics.mediumImpact` on delete (T04). FAB navigates to form. Empty state = `EmptyState` (`sports_gymnastics`, `emptyExercises*` ARB keys) with a CTA that opens the exercise form (T03).
- **Form screen**: Text field for name, `DropdownButtonFormField` with `'weightlifting'` / `'cardio'` options. Uses `Exercise.copyWith()` for edit mode. Only reached for unlocked (user-created) exercises.
- **List sync menu (selective-sync-catalog T04)**: the AppBar sync action is a `PopupMenuButton` — **Sync all** runs the bulk `SyncService.syncExercises` pull (silent on success, error top banner) and **Select…** refreshes the `ExerciseCatalog` (unreachable → blocking banner), opens `showSelectSheet` over `searchHideImported` rows with live Bearer `Image.network` thumbnails (`DisplayItem.imageHeaders`; 404 → fallback icon), and imports only the checked ids via `importSelectedExercises` (offline `jpg/mp4` download at import time). Both paths invalidate `exerciseListProvider`. ARB: `syncAll`, `syncSelect`, `selectServerExercises`, `syncNothingNew`.
- **Catalog build tooling (T07)**: `dart run tool/build_catalog.dart` reads every `data/parsed/*.json` (git-ignored source), applies the cardio heuristic v2 (name regex v2: jump squat/plyo/box jump/step-up/high knee/mountain climber/stationary bike/sled/run/walk/cycle/row/jump rope/burpee/stair/swim/elliptical/cardio/… **plus** `body_part ∈ {Cardio, Plyometrics}`), canonicalizes equipment (`Band`→`Resistance Band`, `Olympic barbell`→`Barbell`), and parses the scraped FAQ blob into structured JSON `[{"q","a"},…]` (fallback: raw text when <1 pair parses). `videoPath` is set **only** for allowlisted slugs (`tool/video_allowlist.txt`). Writes `assets/exercises.db` (SQLite, schema matching the v8 live `exercises` table; all rows `is_locked = 1`; deterministic ids = parsed-filename slug; fixed `createdAt` epoch so rebuilds are reproducible; skips malformed JSON with a WARN). Current output: 3,799 exercises, 341 cardio / 3,458 weightlifting, 3,561 with image, 16 with video, 3,790 with structured FAQs. `tool/prepare_media.sh` copies `data/images/*.png` → `assets/exercises/images/`, prunes **non-allowlisted** videos from `assets/exercises/videos/`, and copies/transcodes only allowlisted videos (360p via ffmpeg when installed, plain copy otherwise). Media sources (`data/`) are git-ignored; the 16 videos are registered as **explicit per-file `pubspec.yaml` asset entries** (a directory entry would bundle everything).
- **Catalog source (server-synced)**: the exercise catalog is **not bundled** any more. The build script (`tool/build_catalog.dart`), the media prep (`tool/prepare_media.sh`), the video allowlist and `assets/exercises.db` were all removed from the repo. The catalogue now comes from the Maia server: `GET /exercises/catalog` returns a lightweight index (id, name, type, media flags), which the app stores in the minimal `ExerciseCatalog` table, and the bulk `GET /exercises` pull fills the full rows. A background refresh runs on a 15-minute throttle (`app/app.dart` `_refreshSelectiveCatalogs`, best-effort and silent), so a missing server configuration is a no-op and the app still starts.
- **Catalog import + media**: the selective import (`importExercises`) writes the chosen rows into the live `exercises` table — upsert by id, locked rows refreshed in place via `ExerciseRepository.updateCatalog`, user-created exercises never touched — and downloads each imported exercise's image and video from the server into `<application documents>/exercise_media/` (`ExerciseMediaDownloader`). Files persist across restarts; a missing file simply re-downloads on the next sync. The old first-launch importer is gone, and so is the one-time `catalog_imported_v9` prefs flag.

## Wiring

The Exercise tab (`lib/src/app/tabs/exercise_tab.dart`) renders `ExerciseListScreen` directly. Exercise definitions are also reachable from the workout-form search picker. The catalog refresh is wired in `lib/src/app/app.dart` (`_refreshSelectiveCatalogs`), and the selective import runs from the exercise list's AppBar sync menu.

## Search, grid and detail (Phase EG, 2026-11-27)

- Reached from the dumbbell icon on the training home. Browsing (no query, no filter) shows a
  two-column image grid; a query or any facet switches to rows with body part · equipment and the
  last logged set (`lastSetPerExerciseProvider`). Swipe-to-delete stays on the rows.
- Facets are dropdown chips — Body part, Equipment, Muscle, Type — that show the picked values; the
  sheet's button counts results live ("Show N exercises").
- Detail: media + History / Details tabs. History = Best / Last / Sessions tiles, one chart with a
  Weight / Reps / Volume switch (Duration / Reps for cardio), then the per-workout session cards
  (set grid, Δ, PR; the first-ever session is never a PR). Details = grouped rows (type, body part,
  equipment, muscles), instructions, tips, FAQs, and a `DangerRow` delete that refuses (with the
  reason) while a workout or template uses the exercise, and otherwise confirms first
  (`confirmDelete(alwaysConfirm: true)`). Edit is in ⋮.
