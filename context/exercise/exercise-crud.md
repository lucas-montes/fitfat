# Exercise Definition CRUD + Catalog — Exercise Domain

Feature: create, read, update, and delete exercise definitions (name + type: weightlifting/cardio), plus the bundled exercise catalog (schema v8 metadata + locked rows), its first-launch import/refresh, search + tag filters, and the tabbed detail/history screen.

## Files

| File | Purpose |
|------|---------|
| `lib/src/exercise/repositories/exercise_repository.dart` | Drift DAO wrapping the `exercises` table (incl. v8 metadata columns) |
| `lib/src/exercise/providers/exercises.dart` | Riverpod providers (`exerciseRepositoryProvider`, `exerciseListProvider`, `exerciseByIdProvider`) |
| `lib/src/exercise/exercise_filter.dart` | Pure helpers: `splitTags`, `canonicalEquipmentTag`, `exerciseFilterOptions`, `filterExercises` |
| `lib/src/exercise/screens/exercise_list.dart` | Search + Type/Body part/Equipment/Muscle filter chips, tap → detail, long-press → edit, swipe-to-delete |
| `lib/src/exercise/screens/exercise_form.dart` | Form with name + type dropdown |
| `lib/src/exercise/screens/exercise_detail_screen.dart` | Pinned header (media + name + fact chips) + History/Details tabs |
| `lib/src/exercise/services/catalog_importer.dart` | First-launch import + refresh of the bundled catalog into the live DB (T08) |
| `tool/build_catalog.dart` | Build script: `data/parsed/*.json` → `assets/exercises.db` (T07) |
| `tool/prepare_media.sh` | Prunes non-allowlisted videos; copies images + allowlisted videos into `assets/exercises/` (T07) |
| `tool/video_allowlist.txt` | Curated video slugs (16) bundled with the app |

## Key behavior

- **Repository** (`exercise_repository.dart`): Uses `ExercisesCompanion.insert()` for inserts and `ExercisesCompanion()` for updates. `updateCatalog(Exercise)` (filters/metadata cleanup) writes all metadata columns for a locked row (used by the importer refresh). Orders results alphabetically by name. `usageCount(String id)` (T06) returns how many `workout_exercises` rows reference the exercise (single `SELECT COUNT(*)` via `selectOnly`) — used to block deletion of exercises still used in workouts. The v8 metadata columns round-trip through `insert`/`_toDomain` (`isLocked`, `bodyPart`, `equipment`, `primaryMuscle`, `secondaryMuscle`, `instructions`/`tips`/`keywords` as JSON-encoded `List<String>`, `faqs` (structured JSON `[{"q","a"},…]`), `imagePath`, `videoPath`).
- **Helper** `newExercise()`: Creates a domain `Exercise` with a fresh UUID v7 and `DateTime.now()`; user-created exercises are not locked.
- **Providers** (`exercises.dart`): `exerciseRepositoryProvider`, `exerciseListProvider` (FutureProvider), `exerciseByIdProvider` (FutureProvider.family, resolves to `null` when the id doesn't exist — the detail screen's not-found state). `exerciseHistoryProvider` lives in `lib/src/exercise/providers/workouts.dart` (family by exercise id → `WorkoutRepository.getExerciseHistory`). All use shared `databaseProvider` from `lib/src/database/database_provider.dart`.
- **List screen**: `ConsumerStatefulWidget` with a **search field** + **filter chips** (Type / Body part / Equipment / Muscle) that open a searchable multi-select bottom sheet (`_FilterOptionsSheet`, checkboxes + Clear/Apply). Query matches name **or keywords** (hidden from display) **or muscles**; filters are AND-ed. A results-count row + "Clear all" appears when filters are active; `_FilteredEmptyState` when nothing matches. Filtering is backed by pure helpers in `exercise_filter.dart` (`exerciseFilterOptions` derives distinct sorted options from the loaded list; `filterExercises` applies query + tag filters; `canonicalEquipmentTag` maps `Band`→`Resistance Band` / `Olympic barbell`→`Barbell` so combined values filter consistently). Tile interactions unchanged: **tap → `ExerciseDetailScreen(exerciseId:)`** (T06); **long-press → edit form** — blocked for locked exercises with the `exerciseLockedEdit` SnackBar (T06). `Dismissible.confirmDismiss` first blocks locked exercises with the `exerciseLockedDelete` SnackBar, then checks `usageCount(id)` (T06): if > 0 it shows the blocking `exerciseUsedTitle` + `exerciseUsedBody(count)` (plural) dialog with `commonOk` and returns false — the tile snaps back, nothing is deleted/throws; unused exercises pass through to a plain hard delete with **no Undo** (user decision, T07). `Haptics.mediumImpact` on delete (T04). FAB navigates to form. Empty state = `EmptyState` (`sports_gymnastics`, `emptyExercises*` ARB keys) with a CTA that opens the exercise form (T03).
- **Form screen**: Text field for name, `DropdownButtonFormField` with `'weightlifting'` / `'cardio'` options. Uses `Exercise.copyWith()` for edit mode. Only reached for unlocked (user-created) exercises.
- **Catalog build tooling (T07)**: `dart run tool/build_catalog.dart` reads every `data/parsed/*.json` (git-ignored source), applies the cardio heuristic v2 (name regex v2: jump squat/plyo/box jump/step-up/high knee/mountain climber/stationary bike/sled/run/walk/cycle/row/jump rope/burpee/stair/swim/elliptical/cardio/… **plus** `body_part ∈ {Cardio, Plyometrics}`), canonicalizes equipment (`Band`→`Resistance Band`, `Olympic barbell`→`Barbell`), and parses the scraped FAQ blob into structured JSON `[{"q","a"},…]` (fallback: raw text when <1 pair parses). `videoPath` is set **only** for allowlisted slugs (`tool/video_allowlist.txt`). Writes `assets/exercises.db` (SQLite, schema matching the v8 live `exercises` table; all rows `is_locked = 1`; deterministic ids = parsed-filename slug; fixed `createdAt` epoch so rebuilds are reproducible; skips malformed JSON with a WARN). Current output: 3,799 exercises, 341 cardio / 3,458 weightlifting, 3,561 with image, 16 with video, 3,790 with structured FAQs. `tool/prepare_media.sh` copies `data/images/*.png` → `assets/exercises/images/`, prunes **non-allowlisted** videos from `assets/exercises/videos/`, and copies/transcodes only allowlisted videos (360p via ffmpeg when installed, plain copy otherwise). Media sources (`data/`) are git-ignored; the 16 videos are registered as **explicit per-file `pubspec.yaml` asset entries** (a directory entry would bundle everything).
- **Catalog first-launch import + refresh (T08)**: `CatalogImporter.run()` runs at startup (before `runApp`, after the DB opens) — guarded by the one-time prefs flag `catalog_imported_v9` (skip when already set; a missing asset degrades silently and retries next launch, never burning the flag). `importInto(database, bytes)` materializes `assets/exercises.db` bytes as a temp file, reads rows via `sqlite3`, and **upserts by id**: existing locked rows are refreshed in place via `ExerciseRepository.updateCatalog` (metadata updated, flag stays set), missing rows are inserted **skip-by-name** (existing user exercises are never touched). Sets the flag when done. Idempotent; re-runs are no-ops. `@visibleForTesting` for `importInto`. Note: per user decision the catalog DB + media are git-ignored (not committed) — the build script + media prep must be run before building.
- **Detail screen (T09)**: `ExerciseDetailScreen` (`exercise_detail_screen.dart`) watches `exerciseByIdProvider` + `exerciseHistoryProvider`. Layout: a **pinned header** — `_MediaHeader` (bundled image at `imagePath`; a `video_player` asset at `videoPath` with play/pause when present — a failed video init falls back to the placeholder icon; empty when no media), then name, then `_FactChips` (type / body-part / equipment chips via `splitTags` + `canonicalEquipmentTag`). Below the header a **History | Details `TabBar`** (keywords are never shown; they're only searchable). **History tab** = `_HistoryMetrics` summary + chart + per-workout cards (see below). **Details tab** = numbered `_InstructionSection` + bulleted tips (both rendered through `_RichText`, which renders `**bold**` segments), `_FaqSection` (decodes the structured JSON `[{"q","a"},…]` into Q/A blocks; falls back to raw `_RichText` when unparseable), and `_MusclesSection` (primary/secondary muscle chips). History = `WorkoutRepository.getExerciseHistory(id)` (`exerciseHistoryProvider`): every `workout_exercises` row for the exercise with its workout + ordered sets, sorted by workout date desc. `_HistoryMetrics` aggregates best set/PR (best `effectiveWeightKg` — or best `durationMinutes` for cardio-only), total workouts/sets, and `chartSpots` + `trendSpots` (both chronological per-workout: total volume — or duration when the exercise never uses weight — plus best-set weight / total reps) → `_HistorySummary` stat tiles + two `fl_chart` `LineChart`s (`_HistoryChart`, ≥ 2 points, date x-labels + tooltip): the volume/duration-over-time chart and a best-weight (or reps) trend. Per-workout cards (`_WorkoutHistoryCard`, newest-first): a right-aligned **summary row** (volume/duration, total reps, distance, sets-completed `n/m`), then a **Δ-vs-previous-workout header** (`_TrendHeader`: total-volume arrow with green/red/neutral trend + a "New PR" pill when the workout's volume beats every older one), then **planned-vs-actual** volume-adherence % and sets-completed % (`Σ effectiveReps×effectiveWeightKg ÷ Σ planned reps×weight`) progress bars, and a **set column grid** (`_SetGridHeader` + `_SetRow`: `Set | Planned | Actual | Δ | Rest`, flex columns with tabular figures; completed sets show a check; Δ is color-coded green/red/amber by direction with reps/weight deltas; rest shows `planned → took` when they differ). Empty state = `exerciseDetailHistoryEmpty`.

## Wiring

The Exercise tab (`lib/src/app/tabs/exercise_tab.dart`) renders `ExerciseListScreen` directly. Exercise definitions are also reachable from the workout-form search picker. The catalog import is wired in `lib/main.dart` startup.
